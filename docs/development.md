## 문제 해결과 개선 과정

| 단계 | 수행한 내용 |
| --- | --- |
| **1. 업무·보호 기준 조사** | 멘토의 조언을 바탕으로 ISMS-P 인증기준 안내서, 개인정보 영향평가 수행안내서 등 개인정보·금융 보안 자료를 검토했습니다. |
| **2. 항목·가중치 설계** | 고유식별·민감·금융·인증·일반 개인식별·거래 정보 등을 나누고, 반복 실행과 결과 검토를 통해 배점과 정보 조합 규칙을 조정했습니다. |
| **3. 서식별 추출 정교화** | 65개 공통 평가 항목에 더해 각 금융 서식에서 빠지면 안 되는 항목과 적용 조건을 추출·검증 규칙으로 작성했습니다. |
| **4. 예외·오탐 개선** | 고정 안내와 실제 기재값, 빈칸과 금액 0, 선택하지 않은 분기 등을 구분하고 누락과 판독 확인 경로를 정리했습니다. |
| **5. 서비스·제출 자료 구성** | 등급에 따라 필요한 마스킹만 호출하는 웹 데모를 구현하고, 데이터셋·정답지·유형표·설계서·실제 노드 캡처를 정리했습니다. |

**문서별 실행 결과를 검토하며 프롬프트·추출 스키마·검증 규칙·가중치를 반복 개선했습니다.**

## 데이터셋과 검증 범위

가상·공개 문서를 기반으로 구성한 최종 데이터셋입니다.

| 유형 | PDF 수 | 확인하는 상황 |
| --- | ---: | --- |
| 단순 문서 | 11 | 실제 값이 기재된 기본 금융 서식 |
| 양식·문맥 다양성 | 3 | 제목·배치·표현이 다른 입력 |
| 문서 결합 | 2 | 서로 다른 서식 4종씩 포함한 결합 입력 |
| 저품질 | 6 | 흐림·기울어짐·무늬 등 판독 조건 |
| 예외·함정 | 10 | 필수값·페이지 누락, 공개 법인정보 등 |
| **합계** | **32** | 결합 문서를 나누어 세면 **38개 문서** |

정답지의 공통 비교 키는 `판정`입니다. 등급 경로의 `개인정보 위험 등급`과 검토 경로의 `판정`을 이 비교 항목에 대응시킵니다. 결합 PDF는 `answer.문서별`에 문서별 결과를 함께 기록했습니다.

이 수치는 데이터셋의 구성 범위이며, 정확도나 성능 점수를 의미하지 않습니다.

## 기술 구성

| 영역 | 사용 기술 |
| --- | --- |
| 웹 화면 | HTML · CSS · JavaScript |
| 서버 | Python · FastAPI · Uvicorn |
| 문서 워크플로우 | Upstage Studio · Agents API · Parse · Classify · Extract · Validate · Instruct |
| API 연동 | OpenAI Python SDK의 호환 API 클라이언트 |
| PDF 처리·미리보기 | PyMuPDF |
| 비동기 작업·병렬 호출 | Python Threading · ThreadPoolExecutor |
| 협업 | GitHub Organization · 브랜치 · Pull Request |
